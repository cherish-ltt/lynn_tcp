# 补充 examples 目录示例 — 实施计划

## 概述

当前 `examples/` 目录下仅有一个 `metrics_example.rs` 示例，且该示例需要 `--features metrics` 才能运行。本计划在 `examples/` 下补充 **3 个独立的、可直接运行的示例**，覆盖项目的核心 API 使用场景：

1. **基础 TCP 服务器示例** — 展示默认配置启动服务器、注册多个路由处理器、发送/不发送响应
2. **自定义配置 TCP 服务器示例** — 展示 `LynnServerConfigBuilder` 自定义地址/连接数/任务池等配置
3. **自定义消息编解码示例** — 展示自定义消息头/尾标记，以及解析消息 payload

这三个示例均使用 `--features server`（默认 features 包含 server），无需额外 feature 即可运行。

## 对现有代码的假设

1. `LynnServer` 的 `start()` 是异步启动的，示例中 `let _server = ...start().await` 后服务器已开始运行
2. `HandlerResult::new_with_send(method_id, response_data, target_addrs)` 需要 `Bytes` 类型的 `response_data`
3. 默认 feature 包含 `server` 和 `client`，因此 `server` feature 已启用
4. 所有 `examples/*.rs` 文件被 Cargo 自动识别为示例（无需在 Cargo.toml 中声明 `[[example]]`）

## 路由处理器签名汇总

根据代码库的分析，目前支持的 handler 参数模式有 3 种：

| # | 参数 | 用途 |
|---|------|------|
| 1 | `() -> HandlerResult` | 无参数，简单触发 |
| 2 | `(InputBufVO) -> HandlerResult` | 接收客户端消息内容 |
| 3 | `(ClientsContext) -> HandlerResult` | 获取所有在线客户端地址，可广播消息 |

这三种签名分别在 `impl_for_context.rs` 中通过 `SystemParam` trait 实现，所有示例都会覆盖这三种模式。

## 注意事项

1. 示例监听端口各不相同，避免端口冲突：
   - `basic_server` — 9177（默认）
   - `custom_config_server` — 9876
   - `custom_protocol` — 9178
2. 示例代码中 **不加 `#[cfg(feature = "metrics")]` 条件编译**，因为 `server` feature（默认已包含）已足够
3. 示例代码遵循现有 `examples/metrics_example.rs` 的风格和格式
4. 所有示例使用 `#[tokio::main]` 和 `Result<(), Box<dyn std::error::Error>>` 作为 main 签名
5. 示例中 handler 函数必须是 `pub` 的（因为 `add_router` 需要 `IntoSystem` trait），遵循已有模式
