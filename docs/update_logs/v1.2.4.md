# v1.2.4 变更日志

发布日期：2025-12-25

## 概述

本版本引入了强大的连接限流功能和大量新的可配置参数，显著提升了服务器的安全性和可配置性。新增了 IP 级别连接限制、连接速率限制、TCP 参数配置等功能，为生产环境部署提供了更精细的控制能力。

## 主要改进

### 🔥 核心功能

#### 1. 连接限流机制
**新文件**：`src/app/connection_limiter.rs`

实现了两层连接限流保护：

**1.1 IP 级别连接限制**
- 限制单个 IP 地址的最大并发连接数
- 防止单个客户端占用过多服务器资源
- 支持 IPv4 和 IPv6

```rust
pub struct IpConnectionLimiter {
    max_connections_per_ip: usize,
    ip_connections: Arc<DashMap<IpAddr, usize>>,
}
```

**1.2 连接速率限制**
- 使用滑动窗口算法限制每秒允许的最大新连接数
- 有效防止 DDoS 攻击和连接风暴
- 自动清理过期记录，防止内存泄漏

```rust
pub struct RateLimiter {
    max_tokens: u64,
    window_duration: Duration,
    tokens: Arc<RwLock<HashMap<IpAddr, Vec<Instant>>>>,
}
```

**1.3 组合限流器**
```rust
pub struct ConnectionLimiter {
    rate_limiter: Option<RateLimiter>,
    ip_limiter: Option<IpConnectionLimiter>,
}
```

**特性**：
- ✅ 独立启用/禁用每种限流
- ✅ 线程安全的并发访问
- ✅ 自动定期清理过期数据
- ✅ 详细的日志记录
- ✅ 完整的单元测试覆盖

## 技术实现细节

### 连接限流流程

```
客户端连接请求
    ↓
1. 应用 TCP 配置（TCP_NODELAY、keep-alive 等）
    ↓
2. 检查全局最大连接数
    ↓
3. 检查 IP 级别连接限制（每个 IP 的并发连接数）
    ↓
4. 检查连接速率限制（滑动窗口算法）
    ↓
5. 所有检查通过 → 接受连接
   任一检查失败 → 拒绝连接并记录日志
```

### 滑动窗口算法

```rust
// 伪代码
fn check_rate_limit(ip: IpAddr) -> bool {
    let now = Instant::now();
    let window_start = now - WINDOW_DURATION;

    // 移除窗口外的时间戳
    timestamps.retain(|&ts| ts > window_start);

    // 检查是否可以添加新连接
    if timestamps.len() < MAX_TOKENS {
        timestamps.push(now);
        true  // 允许连接
    } else {
        false  // 拒绝连接
    }
}
```

### TCP 配置应用

```rust
// 1. 设置 TCP_NODELAY
socket.set_nodelay(config.nodelay)?;

// 2. 转换为 std::net::TcpStream 以使用 socket2
let std_socket = socket.into_std()?;
let socket2 = Socket::from(std_socket);

// 3. 设置 TCP keep-alive
if config.keepalive_enabled {
    let ka = TcpKeepalive::new()
        .with_time(Duration::from_secs(config.keepalive_time_secs));
    socket2.set_tcp_keepalive(&ka)?;
}

// 4. 设置缓冲区大小
if config.recv_buffer_size > 0 {
    socket2.set_recv_buffer_size(config.recv_buffer_size)?;
}
if config.send_buffer_size > 0 {
    socket2.set_send_buffer_size(config.send_buffer_size)?;
}

// 5. 转换回 tokio::net::TcpStream
let socket = TcpStream::from_std(socket2.into())?;
```

## 性能影响

### 内存开销

| 组件 | 内存占用 | 说明 |
|------|---------|------|
| `ConnectionLimiter` | ~100 bytes | 固定开销 |
| `RateLimiter` per IP | ~100 bytes + timestamps | 动态分配 |
| `IpConnectionLimiter` per IP | ~50 bytes | DashMap entry |
| **总计（1000 连接）** | ~150-200 KB | 可接受 |

### CPU 开销

- **速率限制检查**：O(n)，n 为窗口内的时间戳数（通常 < 100）
- **IP 连接计数**：O(1)，DashMap 高效并发访问
- **TCP 配置应用**：一次性操作，仅连接建立时

### 性能优化

1. **使用 DashMap**：高并发下的无锁或低锁竞争
2. **定期清理**：防止长时间运行导致的内存泄漏
3. **可选启用**：用户可以根据需求选择是否启用限流

## 已知问题

### 限制

1. **速率限制精度**：基于系统时钟，极端情况下可能有 ±10ms 误差
2. **IPv6 地址处理**：将 IPv6 地址视为单个实体，不支持前缀聚合
3. **TCP 配置失败**：某些系统可能不支持特定 TCP 选项（已自动降级）
