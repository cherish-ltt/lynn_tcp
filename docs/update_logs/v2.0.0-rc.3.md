# v2.0.0-rc.3 变更日志

发布日期：2026-09-05

## 概述

v2.0.0-rc.3 是一次以**生产级能力补全**为主题的版本，一次性落地三项核心特性：

1. **TLS 1.3 传输加密**（服务端 + 客户端，可选 feature，默认关闭）；
2. **客户端断线自动重连**（默认 3 次，可配置）；
3. **全局状态注入**（axum 风格的 `AppState<T>`，内置 SeaORM 支持）。

同时在测试驱动下修复了一个遗留的客户端读泵**无限自旋缺陷**（TLS 场景必现），并对 handler 执行增加了 panic 隔离保护。所有公共 API 均向后兼容，新增能力全部通过可选 API 与 feature 提供。

## 主要变更

### 1. feat — TLS 1.3 传输加密（feature `tls`，默认关闭）

- 新增 `infrastructure/tls` 模块：`TlsServerConfig` / `TlsClientConfig` 配置类型与 rustls 构建器（`ring` provider），**仅启用 TLS 1.3 协议版本**。
- **服务端**：`LynnServerConfigBuilder::with_tls(TlsServerConfig)` 或 `with_tls_cert_paths(cert, key)` 手动开启；证书缺失/私钥不配对在启动时立即报错；TLS 握手在 reactor worker 内执行（10s 超时上限），不阻塞 accept 循环；握手失败直接关闭该连接。支持 `with_client_ca(...)` 开启双向 mTLS。
- **客户端**：`LynnClientConfigBuilder::with_tls(TlsClientConfig)`，支持 CA 信任锚（默认强制校验）、SNI 名称覆盖、客户端证书（mTLS）与开发用 `danger_accept_invalid_certs`（带告警日志）。TLS 配置错误在连接前快速失败。
- 传输抽象：新增 `LynnStream` 枚举（明文/TLS），连接管道（`LynnUser`、`add_client`、`push_read_half` 等）统一改用 boxed 读写半部，不再耦合具体传输类型。
- 新增 `LynnError::Tls` 错误变体与 `lynn_tcp::lynn_tls` 公共模块（含 `rustls` 再导出）。
- 依赖（可选）：`tokio-rustls = 0.26.5`、`rustls = 0.23.43`、`rustls-pemfile = 2.2.0`。

### 2. feat — 客户端断线自动重连

- 新增 `application/client/client_connection.rs` 连接监督者：初始连接与断线重连共用同一策略——**默认 3 次尝试、间隔 1s**，可通过 `with_reconnect_max_attempts` / `with_reconnect_interval_secs` / `with_connect_timeout_secs` 配置。
- 用户侧收发通道**跨重连复用**：写通道经共享 `Mutex` 由监督者持有，读通道保持不变；重连成功后自动恢复收发，断线期间积压的过期帧（如心跳）被丢弃以避免背压积压。
- 新增 `LynnClient::is_connected()`：基于 `watch` 通道的实时连接状态查询。
- 客户端销毁后监督者自动退出（检测接收端关闭）。
- 每次连接尝试均带超时（TCP 连接与 TLS 握手分开计时）。

### 3. feat — 全局状态注入（`AppState<T>`）与 SeaORM 支持（feature `seaorm`，默认关闭）

- 新增 `domain/state` 模块：`StateRegistry`（按 `TypeId` 键控的共享状态容器，服务端实例私有）与 `AppState<T>` 提取器。
- Handler 参数**声明即注入**：`async fn h(repo: AppState<MyDb>, input: InputBufVO) -> HandlerResult`，`AppState<T>` 解引用为 `&T`，支持任意多个状态参数与多状态类型共存。
- `LynnServer::with_state(T)` / `with_state_arc(Arc<T>)` 注册状态；解析发生在请求处理时，注册顺序与 `add_router` 无关（`start()` 前注册即可）。
- `seaorm` feature：`LynnServer::with_db(DatabaseConnection)` 便捷方法与 `lynn_seaorm::DbConn`（= `AppState<DatabaseConnection>`）别名，依赖 `sea-orm = 2.0.2`（`runtime-tokio-rustls`），数据库后端由用户侧 sea-orm 依赖通过 feature 统一决定。
- 未注册状态的提取会 panic，但被 reactor 的 handler panic 隔离捕获（见第 5 条），不影响服务存活。

### 4. fix — 客户端读写泵传输错误无限自旋（TLS 场景必现）

客户端读循环在 `read` 错误时仅记日志不退出：明文 TCP 下错误通常伴随连接关闭不易复现；而 TLS 会话拆除后每次 poll **立即**返回同一错误，导致读泵无限自旋刷日志、tokio worker 永久停留在 poll 内、运行时 drop 阻塞、进程无法退出。修复：读循环（read 错误、接收端关闭）与写循环（write 错误）在传输错误时终止。

### 5. refactor — 连接传输抽象与 handler panic 隔离

- 读写半部 boxed 化（`Box<dyn AsyncWrite + Send + Unpin>` 等），为 TLS 与未来的传输扩展铺路；reactor 事件通道由 9 元组重构为 `NewSocketTask` 结构体。
- **handler 执行改为嵌套任务**：单个 handler 的 panic（如误用未注册的 `AppState`）只会终止该请求并被记录，不再打崩 reactor worker（原实现会让 worker 池逐个损失容量）。

### 6. feat — 标准化基准测试工具（替代 1.x 一次性压测脚本）

- 新增 `benches/benchmark.rs`（`cargo bench --bench benchmark`）：双流量模型（Model-1 ping-pong 逐请求测 RTT 分位数；Model-2 收发并发流水线测持续吞吐），参数化 CLI（`--model/--clients/--duration/--warmup/--payload/--json`），输出 Markdown 表与 JSON 存档。
- 新增 `src/bin/bench_echo_server.rs`：echo server 以**独立进程**运行（与真实部署一致），每格基准使用全新 server 进程，杜绝跨格状态污染；协议层默认的每 IP 10 连接/100 conn/s 限速在压测 server 中显式放开。
- 标准矩阵：模型 1+2 × 并发 64/256/1024/4096（对数 4× 步长），载荷 128 B，3s 预热 + 10s 测量；README「Benchmarks」章节替换 1.x 旧表，结果 JSON 存档于 `docs/benchmark/`。
- 本机首测（Apple M1 Pro，8 逻辑核 / 16 GB，回环）：Model-1 峰值 **144,873 resp/s**（1024 客户端，p50 5.7ms）；Model-2 峰值 **131,482 resp/s**（256 客户端）。
- 基准开发过程中发现并修复：客户端连接监督者的 `is_connected()` 竞态（见第 2 条附带修复：`start()` 返回时连接状态必然可见）。

### 7. build / ci / docs

- CI 新增 `cargo check --all-features --all-targets` 与 `cargo test --all-features` 步骤，确保 feature 门控代码始终参与验证（AGENTS.md 第 2、10.7 节同步更新）。
- 新增示例：`state_example`（全局状态）、`tls_example`（TLS 1.3，`required-features = ["tls"]`）。
- 新增集成测试套件：`tests/state_injection.rs`（5 用例）、`tests/tls_integration.rs`（3 用例，rcgen 生成临时证书）、`tests/client_reconnect.rs`（3 用例）。
- README / README_ZH 同步更新：特性表、客户端配置表、TLS/全局状态/重连章节、路线图与 FAQ、新「Benchmarks」章节（移除 1.x 旧表）。
- AGENTS.md 第 10.3 节登记 `docs/benchmark/` 与基准测试规范（独立进程 server、静默运行、JSON 存档约定）。

## 向后兼容性

- ✅ **公共 API 不变**：`LynnServer` / `LynnClient` / `HandlerResult` / `InputBufVO` 既有方法签名与默认行为完全兼容。
- ✅ 默认 feature 组合（`server`、`client`）下不引入任何新依赖，编译产物不变（TLS/SeaORM 均为可选 feature）。
- ⚠️ **行为改进**：客户端连接断开期间 `send_data` 会将消息入队（通道满则背压），重连后丢弃过期帧——原实现为静默写失败；`get_receive_data` 在重连等待期返回 `None`。
- ⚠️ handler panic 不再杀死 reactor worker（原先会永久损失一个 worker 容量）。

## 升级指南

### 从 v2.0.0-rc.2 升级到 v2.0.0-rc.3

默认用法无需修改任何代码：

```toml
[dependencies]
lynn_tcp = "2.0.0-rc.3"
```

按需启用新能力：

```toml
[dependencies]
lynn_tcp = { version = "2.0.0-rc.3", features = ["tls", "seaorm"] }
```

- 启用 `tls` 后，在服务端 Builder 上 `with_tls_cert_paths(...)`、客户端 Builder 上 `with_tls(...)` 即开启 TLS 1.3；未调用则保持明文，行为与旧版一致。
- 数据库句柄：`.with_state(db)` 或（`seaorm` feature）`.with_db(db)`，Handler 参数声明 `lynn_state::AppState<T>` / `lynn_seaorm::DbConn`。
- 断线重连默认开启（3 次）；如需调整，使用 `with_reconnect_max_attempts` / `with_reconnect_interval_secs`。
