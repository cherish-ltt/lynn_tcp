# v2.4.2 变更日志

发布日期：2026-11-05

## 概述

根据 [Issue #97](https://github.com/cherish-ltt/lynn_tcp/issues/97)，将可选 KCP 依赖从 kcp-ovo `=0.6.0` 升级至 `=0.8.0`，并适配上游借用切片与 `Vec<u8>` 字节 API。TCP 保持默认，KCP 显式启用；自定义 fast 参数、消息边界、队列上限与传输 ACK 语义不变。

本次是依赖与 API 兼容更新，没有新增上游高层 drain 能力，也未测量 0.8.0 性能。历史性能样本保持原名与原始结果，不作为本版本提速或回归结论。

## 主要变更

### 1. build / fix — 接入 kcp-ovo 0.8.0

- 精确锁定 `kcp-ovo =0.8.0`，核对官方发布包与 tag 源码；Rust 1.99.1、Tokio `=1.52.3`、bytes `=1.11.1` 保持不变。上游虽已放宽 Tokio/bytes 版本范围，本项目仍保留自己的精确约束。
- 头部解析从 `&mut Bytes` 迁移为 `&mut &[u8]`，接收与编码/输出使用上游返回的 `Vec<u8>`；完整数据报仍传给 `Kcp::input`，保留声明长度与实际 payload 相等检查。
- 继续使用底层 `Kcp` 控制块及本项目会话所有权，不接入上游高层 Stream/Listener/drain API；fast/normal、HELLO/DATA/EOF、有界队列、10 MiB body 上限及取消规则不变。
- 同步双语 README、KCP 配置指南、英文版本历史与开发规范；双端配置、迁移和建议场景见 [KCP 指南](https://github.com/cherish-ltt/lynn_tcp/blob/v2.4.2/docs/kcp.md)。

### 2. test — 字节 API 迁移与协议边界

- 迁移依赖契约测试到上游标准库字节类型，保留应用自选全局分配器、fast/normal 连续超时退避与新 RTO 期限、输入缓冲复用、单段/多段及乱序/重复报文恢复回归。
- 补充 27 字节短头、HELLO 声明长度偏短、偏长及尾随字节拒绝回归，并验证非法报文之后仍能正常建立合法会话，防止切片解析迁移放宽准入边界。
- 具体命令、结果与限制见 [0.8.0 升级验证](https://github.com/cherish-ltt/lynn_tcp/blob/v2.4.2/docs/kcp-v0.8.0-validation.md)。

## 向后兼容性

- 默认 feature、普通 builder、合法线路格式与业务 handler 用法不变；TLS+KCP 和原生 `stream_mode=true` 仍明确拒绝。
- **`KcpConfig.protocol` 与 `lynn_kcp::KcpOptions` 使用上游 0.8.0 配置类型。** 直接传入另行依赖的 kcp-ovo 0.6.0 或更早版本配置的应用，须同步升级至 0.8.0，或改用本库重导出；补丁版本不代表所有下游源码无条件兼容。
- KCP 仍无认证和加密，不兼容标准 KCP 或上游高层 API；fast 的 `nocwnd=true` 不保证共享链路公平性。敏感或不可信链路继续使用 TCP+TLS。
- flush 的传输 ACK 不代表业务交付，Drop 不承诺排空；严格交付仍须应用协议确认。

## 测试结果与限制

仅升级依赖时，两处头部解析调用因 `&mut Bytes` 与 `&mut &[u8]` 不匹配而无法编译；完成适配后，`cargo check --locked --features kcp --all-targets` 通过。KCP 模块单元测试 11、依赖契约 4、独立进程 1、传输集成 9 项全部通过。

默认测试 171 项、全 feature 测试 225 项通过（含 7 doctest）；metrics 黑盒收到 400/400 回复，双向字节各 9200 B 精确匹配，5/5 连接关闭。0.6.0/0.8.0 两个互通方向的 fast/normal 四格均为 816/816 精确回复，共 3264/3264（含 64 个大 payload）；这是 macOS arm64 有限回环互通验证，不是性能或生产滚动升级保证。

关闭默认功能后的十种独立 feature 组合检查与测试全部通过，0 failed / 0 ignored；带 `kcp` 的打包预检通过，并实际构建包内 v2.4.2 与 kcp-ovo 0.8.0。独立 `PREK_HOME` 下全量 `prek` 的 13 个 hooks 均通过，无 warning。

独立覆盖率运行通过 218 项测试，生产代码行覆盖率 **93.05%（4166/4477）**。LLVM 23.1.1 的 663 条占位映射警告仍保留；已逐符号核对真实计数，并与空 profile 和完整映射基线逐项确认分母一致，详见验证报告，不声称覆盖率过程无 warning。

本次兼容验证单独记录在 [0.8.0 验证报告](https://github.com/cherish-ltt/lynn_tcp/blob/v2.4.2/docs/kcp-v0.8.0-validation.md)。旧版测试数量、覆盖率与性能结果不移用为本版本证据；GitHub Release 与 crates.io 正式发布分别核验，发布后证据关联 [Issue #97](https://github.com/cherish-ltt/lynn_tcp/issues/97)。

本次不包含 0.8.0 性能矩阵，也未验证公网跨主机、Windows、长时间 soak、拥塞公平性或 CPU/内存 profile；不声称普遍提速。

## 升级指南

1. 更新为 `lynn_tcp = "=2.4.2"` 并刷新 lock，使用 Rust 1.99.1，确认下游 Tokio/bytes 约束与 `1.52.3` / `1.11.1` 兼容；仅使用 TCP 时无需启用 KCP。
2. 使用 KCP 时，双端启用 `kcp` 并调用 `with_kcp(KcpConfig::default())`；直接传入上游配置的应用同步升级到 kcp-ovo 0.8.0，或使用 `lynn_kcp::KcpOptions`。
3. 按 [KCP 配置与迁移](https://github.com/cherish-ltt/lynn_tcp/blob/v2.4.2/docs/kcp.md) 验证真实 payload、并发和网络条件，保留应用层交付确认，不启用原生 stream mode 或叠加 TLS。
4. 从 v2.4.0 之前升级时，继续应用 [指标迁移](https://github.com/cherish-ltt/lynn_tcp/blob/v2.4.2/METRICS.md#自动采集边界与迁移) 和 [v2.3.0 返回类型变更](https://github.com/cherish-ltt/lynn_tcp/blob/v2.4.2/docs/update_logs/v2.3.0.md#升级指南)。
