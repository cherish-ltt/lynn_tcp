# v2.0.0 变更日志

发布日期：2026-09-11

## 概述

v2.0.0 是 Lynn TCP 的第二个大版本，也是项目从"可用"走向"生产可用"的分水岭。本版本汇总了 `v2.0.0-rc.1` ~ `v2.0.0-rc.3` 三个候选版的全部内容，核心主题有三条主线：

1. **架构重塑**：从扁平单体演进为 **DDD（Domain-Driven Design）+ 洋葱架构**，在不改变任何公共 API 的前提下完成代码结构的大规模重组；
2. **生产级能力补全**：TLS 1.3 传输加密、客户端断线自动重连、全局状态注入（`AppState<T>`）/ SeaORM 集成，全部以**默认关闭的可选 feature** 提供，核心库保持轻量；
3. **工程化与质量保障**：落地 `AGENTS.md` 开发宪法、按规范重构 CI 与工具链、补齐端到端测试（行覆盖率 19.65% → **92.16%**）、建立标准化基准测试工具。

本版本对使用默认配置的用户**完全向后兼容**：既有公共 API 签名、默认行为、feature 组合均无变化，新增能力一律通过可选 API 与 feature 开放。

### 2. fix — 自定义消息标记响应帧缺陷（rc.2）

- **文件**：`src/application/server/server_common.rs`
- `check_handler_result` 中响应帧在 `set_marks` 之前就被 `get_response_data` 编码，导致配置了自定义消息头/尾标记（`with_message_header_mark` / `with_message_tail_mark`）的服务器，其**响应帧始终使用默认标记（9177/7719）**，自定义标记的客户端无法解析响应。使用默认标记的服务器不受影响。
- 修复方式：先应用标记，再编码响应帧（与客户端发送路径的既有顺序一致）。

### 3. feat — TLS 1.3 传输加密（feature `tls`，默认关闭）（rc.3）

- 新增 `infrastructure/tls` 模块：`TlsServerConfig` / `TlsClientConfig` 配置类型与 rustls 构建器（`ring` provider），**仅启用 TLS 1.3**。
- **服务端**：`LynnServerConfigBuilder::with_tls(TlsServerConfig)` 或 `with_tls_cert_paths(cert, key)` 手动开启；证书缺失/私钥不配对在启动时立即报错；TLS 握手在 reactor worker 内执行（10s 超时上限），不阻塞 accept 循环；握手失败直接关闭该连接；支持 `with_client_ca(...)` 开启双向 mTLS。
- **客户端**：`LynnClientConfigBuilder::with_tls(TlsClientConfig)`，支持 CA 信任锚（默认强制校验）、SNI 名称覆盖、客户端证书（mTLS）与开发用 `danger_accept_invalid_certs`（带告警日志）。TLS 配置错误在连接前快速失败。
- 传输抽象：新增 `LynnStream` 枚举（明文/TLS），连接管道统一改用 boxed 读写半部，不再耦合具体传输类型。
- 新增 `LynnError::Tls` 错误变体与 `lynn_tcp::lynn_tls` 公共模块（含 `rustls` 再导出）。
- 依赖（可选）：`tokio-rustls = 0.26.5`、`rustls = 0.23.43`、`rustls-pemfile = 2.2.0`。

### 4. feat — 客户端断线自动重连（rc.3）

- 新增 `application/client/client_connection.rs` 连接监督者：初始连接与断线重连共用同一策略——**默认 3 次尝试、间隔 1s**，可通过 `with_reconnect_max_attempts` / `with_reconnect_interval_secs` / `with_connect_timeout_secs` 配置。
- 用户侧收发通道**跨重连复用**：写通道经共享 `Mutex` 由监督者持有，读通道保持不变；重连成功后自动恢复收发，断线期间积压的过期帧（如心跳）被丢弃以避免背压积压。
- 新增 `LynnClient::is_connected()`：基于 `watch` 通道的实时连接状态查询。
- 客户端销毁后监督者自动退出；每次连接尝试均带超时（TCP 连接与 TLS 握手分开计时）。

### 5. feat — 全局状态注入与 SeaORM 支持（feature `seaorm`，默认关闭）（rc.3）

- 新增 `domain/state` 模块：`StateRegistry`（按 `TypeId` 键控的共享状态容器，服务端实例私有）与 `AppState<T>` 提取器。
- Handler 参数**声明即注入**：`async fn h(repo: AppState<MyDb>, input: InputBufVO) -> HandlerResult`，`AppState<T>` 解引用为 `&T`，支持任意多个状态参数与多状态类型共存。
- `LynnServer::with_state(T)` / `with_state_arc(Arc<T>)` 注册状态；解析发生在请求处理时，注册顺序与 `add_router` 无关（`start()` 前注册即可）。
- `seaorm` feature：`LynnServer::with_db(DatabaseConnection)` 便捷方法与 `lynn_seaorm::DbConn`（= `AppState<DatabaseConnection>`）别名，依赖 `sea-orm = 2.0.2`（`runtime-tokio-rustls`）。
- 未注册状态的提取会 panic，但被 reactor 的 handler panic 隔离捕获，不影响服务存活。

### 6. fix — 客户端读写泵传输错误无限自旋（rc.3）

- 客户端读循环在 `read` 错误时仅记日志不退出：明文 TCP 下错误通常伴随连接关闭不易复现；而 TLS 会话拆除后每次 poll **立即**返回同一错误，导致读泵无限自旋刷日志、tokio worker 永久停留在 poll 内、运行时 drop 阻塞、进程无法退出。
- 修复：读循环（read 错误、接收端关闭）与写循环（write 错误）在传输错误时终止。

### 7. refactor — handler panic 隔离（rc.3）

- 读写半部 boxed 化（`Box<dyn AsyncWrite + Send + Unpin>` 等），为 TLS 与未来的传输扩展铺路；reactor 事件通道由 9 元组重构为 `NewSocketTask` 结构体。
- **handler 执行改为嵌套任务**：单个 handler 的 panic（如误用未注册的 `AppState`）只会终止该请求并被记录，不再打崩 reactor worker（原实现会让 worker 池逐个损失容量）。

### 8. feat — 标准化基准测试工具（rc.3）

- 新增 `benches/benchmark.rs`（`cargo bench --bench benchmark`）：双流量模型（Model-1 ping-pong 逐请求测 RTT 分位数；Model-2 收发并发流水线测持续吞吐），参数化 CLI（`--model/--clients/--duration/--warmup/--payload/--json`），输出 Markdown 表与 JSON 存档。
- 新增 `src/bin/bench_echo_server.rs`：echo server 以**独立进程**运行，每格基准使用全新 server 进程，杜绝跨格状态污染；协议层默认的每 IP 10 连接/100 conn/s 限速在压测 server 中显式放开。
- 标准矩阵：模型 1+2 × 并发 64/256/1024/4096，载荷 128 B，3s 预热 + 10s 测量；结果 JSON 存档于 `docs/benchmark/`。
- 参考结果：Apple M1 Pro（8 逻辑核 / 16 GB，回环）Model-1 峰值 **144,873 resp/s**（1024 客户端，p50 5.7ms）、Model-2 峰值 **131,482 resp/s**（256 客户端）；Debian 13 arm64 2c2g 另有存档。

## 向后兼容性

- ✅ **公共 API 签名不变**（`LynnServer`、`LynnClient`、`HandlerResult`、`InputBufVO` 等既有方法签名与默认行为完全兼容）。
- ✅ **所有模块路径不变**（`lynn_server::*`、`lynn_client::*`、`lynn_tcp_dependents::*`），仅内部模块路径调整（不影响外部使用）。
- ✅ **默认 feature 组合**（`server`、`client`）不引入任何新依赖，编译产物不变；新增能力全部为默认关闭的可选 feature（`tls`、`seaorm`、`metrics`）。
- ⚠️ **自定义标记服务器**：响应帧标记从"错误的默认值"修正为"配置值"（缺陷修复）；若此前有客户端依赖了错误行为，需同步使用正确的自定义标记。
- ⚠️ **客户端行为改进**：断线期间 `send_data` 会将消息入队（通道满则背压），重连后丢弃过期帧（原实现为静默写失败）；`get_receive_data` 在重连等待期返回 `None`。
- ⚠️ **handler panic 不再杀死 reactor worker**（原先会永久损失一个 worker 容量）。
- ⚠️ 仓库文件位置调整：`update_logs/`、`version.md`、`FlowChart.png`、`grafana/`、`prometheus/` 迁移至 `docs/` 下。
- ⚠️ Rust 编译器需要 `>= 1.98.1`。

## 升级指南

### 从 v1.2.x 升级到 v2.0.0

对大多数用户，**无需修改任何代码**，只需更新 `Cargo.toml` 中的版本号：

```toml
[dependencies]
lynn_tcp = "2"
```

按需启用可选能力：

```toml
[dependencies]
lynn_tcp = { version = "2.0.0", features = ["server", "client", "tls", "seaorm"] }
```

- 启用 `tls` 后，服务端 Builder 上 `with_tls_cert_paths(...)`、客户端 Builder 上 `with_tls(...)` 即开启 TLS 1.3；未调用则保持明文，行为与旧版一致。
- 数据库句柄：`.with_state(db)` 或（`seaorm` feature）`.with_db(db)`，Handler 参数声明 `AppState<T>` / `lynn_seaorm::DbConn`。
- 断线重连默认开启（3 次）；如需调整，使用 `with_reconnect_max_attempts` / `with_reconnect_interval_secs`。

### 从 v2.0.0-rc.x 升级到 v2.0.0

rc 候选版内容已全部包含在 v2.0.0 中，直接替换版本号即可，无需其他改动。
