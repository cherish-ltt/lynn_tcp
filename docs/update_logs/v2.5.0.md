# v2.5.0 变更日志

发布日期：2026-11-05

## 概述

本版本新增服务端后台广播与异步请求中间件，分别完成 [Issue #91](https://github.com/cherish-ltt/lynn_tcp/issues/91) / [PR #99](https://github.com/cherish-ltt/lynn_tcp/pull/99) 和 [Issue #95](https://github.com/cherish-ltt/lynn_tcp/issues/95) / [PR #100](https://github.com/cherish-ltt/lynn_tcp/pull/100)。后台任务可以主动向在线连接发送消息，鉴权、请求数据注入、超时和响应处理可以组合为全局或路由级中间件。

两项能力均由 `server` feature 提供，复用现有 TCP/TLS/KCP 连接与发送路径。现有 `add_router` 和普通 Handler 签名无需迁移；不注册中间件时保留直接调用 Handler 的分支。入队、超时和性能均有明确边界，本版本不提供可靠交付或零成本承诺。

## 主要变更

### 1. feat — 服务端后台广播

- 新增 `LynnServer::broadcast_handle()`，返回可克隆的 `lynn_server::BroadcastHandle`；应用可在 `start()` 消费服务端前取得句柄，由自己管理的后台任务调用 `broadcast(method_id, payload: Bytes)`。
- 每次调用记录当前连接的 sender 快照，再向各有界写队列尝试一次非等待入队，返回 `BroadcastReport { enqueued, full, closed }`。空快照返回零计数，满队列或已关闭队列不阻止其他目标入队；既有 Handler 响应仍保留等待背压。
- 句柄使用所属实例的帧标记，不持有服务端 owner 或在线表强引用，不保活 I/O、后台任务或 AppState。启动前或 owner 取消后调用显式报错；快照不会把旧连接的消息重定向给同地址的新连接。
- 复用 payload 长度校验与共用 writer；空 payload 合法，超过 **10 MiB 减 5 字节**返回 `LynnError::Protocol`。队列拒绝计入 dropped，发送消息与字节仍在真实传输边界统计。
- 实现位于 `src/application/server/broadcast.rs`；可运行示例见 [`background_broadcast`](https://github.com/cherish-ltt/lynn_tcp/blob/v2.5.0/examples/background_broadcast.rs)。

### 2. feat — 全局与路由级异步中间件

- 新增 `lynn_middleware` 的 `MiddlewareChain`、`MiddlewareRequest`、`Next`、`RequestContext` 与 `ResponseView`，通过 `with_middleware` 和 `add_router_with_middleware` 注册。全局层包住路由层，按注册顺序进入、逆序返回；启动前冻结，重复路由整体替换 Handler 与本地链。
- `Next::run(self, request)` 消费请求与 Next，只能继续一次。中间件可短路、返回 no-send、映射 `LynnError` 或构造替换响应；响应仍走现有长度校验和统一发送路径，不允许通过中间件重试或重新路由。
- 请求提供只读 method ID、来源地址、payload 和共享 `AppState` 查询；`insert` / `get` 操作本请求独立的类型数据，到达 Handler 时冻结为只读 `RequestContext`。类型表首次插入才分配，缺失值返回 `None`，请求身份不混入全局共享状态。
- 处理许可覆盖排队、整链与最终响应入队，正常 EOF 等待这段处理完成。非空链在现有受 owner 管理的任务内执行，不为每层创建任务池或无界队列；空链不构造 `MiddlewareRequest`、`Next` 或请求类型表。
- 仅已匹配路由的普通入站请求进入中间件；心跳、未知路由、畸形帧和后台主动广播均不进入。未处理错误在根部记录一次并计一次 dropped，不自动回发内部错误、关闭健康连接或重试。
- 可运行的鉴权注入、外层错误映射、timeout/tracing 示例与迁移说明见 [中间件指南](https://github.com/cherish-ltt/lynn_tcp/blob/v2.5.0/docs/middleware.md)；同步双语 README、METRICS 与开发规范。

### 3. test / perf — 生命周期回归与可追溯测量

- 广播回归覆盖满队列隔离、关闭与取消、实例隔离、空/超限 payload、TCP/TLS/KCP 和发送指标；中间件回归覆盖顺序与短路、响应替换、数据隔离、错误/panic/timeout、EOF/owner 取消、处理许可及指标边界。
- 基准 model 1 记录每个客户端的完整窗口与退出原因，预热期退出、超时、内容错误及零测量请求都会判失败；服务停止失败仍保存已完成的客户端计数，并返回非零退出码。
- 独立进程对照保留 baseline、空链、单层透传和鉴权/超时/观测组合的三轮原始 JSON、日志、源码与二进制哈希。所有构建完成后串行测量，具体方法、资源口径和结果见 [中间件性能对照](https://github.com/cherish-ltt/lynn_tcp/blob/v2.5.0/docs/middleware-performance.md)。

## 向后兼容性

- 默认 feature、合法线路格式、现有 `add_router`、普通 Handler 和请求驱动响应的用法不变。广播及中间件需要 `server`；没有新增默认认证策略、业务拒绝帧或默认处理超时。
- 广播的 `enqueued` 只表示本地队列接受，不表示写入完成、传输 ACK 或业务交付；关闭与广播并发时，已接受帧仍可能被丢弃。整次重试可能重复交付，调度、取消、幂等及业务确认由应用负责。
- timeout 只覆盖被包裹的内层 Future，不包含排队、外层返回处理、最终入队及网络发送；它无法抢占不让出执行权的同步代码，也不回滚数据库写入等副作用。panic/取消不保证执行中间件的 async 返回或清理逻辑。
- `processing_duration_seconds` 仍只统计终端 Handler 与参数解析；短路没有 Handler 样本，整链耗时需单独观测。响应映射后的 `Ok` 不等于业务成功，`sent` 与网络字节继续由真实传输统计。
- Rust 1.99.1、Tokio `=1.52.3`、bytes `=1.11.1` 与可选 kcp-ovo `=0.8.0` 保持不变。KCP 仍无加密认证，TLS+KCP 与原生 stream mode 仍拒绝；从旧版上游配置类型迁移的要求见 [KCP 指南](https://github.com/cherish-ltt/lynn_tcp/blob/v2.5.0/docs/kcp.md)。

## 测试结果与限制

功能合并阶段，PR #99、PR #100 及合并后 main `190be310f31feadb311d3c0c74343b036ecc6fe2` 的 CI 分别通过全部 11 个 jobs；最终 PR CI 默认测试 **201** 项、全 feature 测试 **259** 项通过。发布前独立覆盖率运行的生产代码行覆盖率为 **93.52%（4462/4771）**。这些结果对应功能合并阶段，不替代版本更新后的发布预检或正式发布核验。

版本更新至 2.5.0 后，`prek run --all-files` 全部 **13** 项通过，覆盖格式、静态扫描、全 feature check/Clippy/测试；旧 Node 缓存环境存在版本不匹配提示，有效钩子均实际执行通过。修正 SeaORM `DbConn` 的文档链接后，`RUSTDOCFLAGS='-D warnings' cargo doc --locked --all-features --no-deps` 无文档警告通过。`cargo package --locked --allow-dirty --all-features` 完成 243 个文件的打包及包内构建，已核对新 API、示例与更新日志入包；未修改生产逻辑或依赖版本。

发布前性能测量使用 Apple M1 Pro、macOS arm64、Rust 1.99.1，TCP loopback、128 B payload、1/64 客户端、2 秒预热及 5 秒测量窗口。24 格全部 `exit 0`，780 项客户端记录均完成窗口，请求与响应各 **3,892,394** 条，内容校验通过。64 客户端 baseline/empty/pass/composed 的吞吐中位数分别为 **71,281.4 / 63,149.2 / 65,974.2 / 57,766.6 响应/秒**；轮间波动大且比较方向会翻转，不能据此宣称稳定提速或退化。

空链的分配调用数接近基线，但 64 客户端下分配请求字节中位数约增加 **180 B/Handler（6.3%）**，峰值 RSS 中位数约增加 **0.55 MiB**。单层与组合链存在额外分配。分配、CPU 与 RSS 覆盖整个服务端生命周期，计数器本身也扰动性能；本次没有分配堆栈或 Future 布局测量，不精确归因新增字节，不把空链结构测试解释为零资源成本。

原始数据仍位于 [`docs/benchmark/v2.4.2-middleware-apple-m1-pro/`](https://github.com/cherish-ltt/lynn_tcp/tree/v2.5.0/docs/benchmark/v2.4.2-middleware-apple-m1-pro)，保留当时的版本、源码与二进制哈希：baseline 为已合入广播的 `3011b076e92d24e797f72f9125cc0cc431e2237a`，被测中间件工作树源码/Cargo 摘要为 `659feda7fe0293180b95158e5f976c03065bc0b11bb2ea16ae475523082e1d23`。这是版本号仍为 v2.4.2 时的发布前开发测量，**没有在改为 v2.5.0 后重新压测**；不改名或覆盖历史样本。

未验证公网跨主机、Windows、长时间 soak 或真实鉴权/日志负载的性能。发布 CI、GitHub Release 与 crates.io 状态须分别核验；本记录不以功能测试、打包预检或历史测量声明正式发布完成。

## 升级指南

1. 更新为 `lynn_tcp = "=2.5.0"` 并刷新 lock，使用 Rust 1.99.1。已有 v2.4.2 普通路由可保持不变；只启用服务端时使用 `default-features = false, features = ["server"]`。
2. 需要后台推送时，在 `start()` 前取得 `broadcast_handle()`；应用负责启动和停止周期任务，处理 `enqueued/full/closed` 与调用错误，并按业务协议确认交付。可先运行 `cargo run --example background_broadcast`。
3. 需要中间件时，把共用校验放在全局或路由层；验证通过后插入请求身份并调用 Next，Handler 使用 `RequestContext::get` 且显式拒绝缺失身份。将错误映射放在可能失败的层外，按 [中间件指南](https://github.com/cherish-ltt/lynn_tcp/blob/v2.5.0/docs/middleware.md) 设计超时、事务与幂等；可运行 `cargo run --example middleware_example`。
4. 使用 KCP 时沿用 [双端配置、迁移和场景建议](https://github.com/cherish-ltt/lynn_tcp/blob/v2.5.0/docs/kcp.md)，直接导入旧 kcp-ovo 配置的应用升级至 0.8.0 或使用 `lynn_kcp::KcpOptions`。从更早版本升级还须应用 [v2.3.0 返回类型迁移](https://github.com/cherish-ltt/lynn_tcp/blob/v2.5.0/docs/update_logs/v2.3.0.md#升级指南) 和 [指标迁移](https://github.com/cherish-ltt/lynn_tcp/blob/v2.5.0/METRICS.md#自动采集边界与迁移)。
