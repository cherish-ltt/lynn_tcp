# v2.2.0 变更日志

发布日期：2026-11-02

## 概述

本版本修复 10 个 Issue（#46-#55）及安全反馈 [GHSA-4hxf-mfq8-qqxx](https://github.com/cherish-ltt/lynn_tcp/security/advisories/GHSA-4hxf-mfq8-qqxx)，由 8 个 PR（#56-#63）交付。重点是有界协议解析、连接资源回收、实际生效的读写超时，以及独立 feature、监控、IPv6 TLS 和长空闲稳定性。

默认公共 API 用法与合法报文格式保持兼容；错误帧、连接释放、并发配额和非零超时的行为更严格，升级前请检查下文兼容性说明。

## 主要变更

### 1. sec — 有界接收解析与错误帧终止

- 客户端与服务端共用有界解析器，区分完整帧、不完整帧和终止性协议错误；无效头尾、过短或超长帧不再持续累积缓存。
- 协议错误立即结束对应明文或 TLS 传输，包括写端背压时的关闭；正常分片、粘包和最大合法帧仍可处理。
- 单解析器保留数据上限为 10 MiB + 10 字节帧头 + 1 KiB 单次读取；这不是分配器、发送队列或进程总内存的上限。
- 涉及：`big_buf_reader.rs`、服务端/客户端读取循环；PR #57。

### 2. fix — 连接生命周期与处理许可

- 配额所有权在接受连接、TLS 握手及读写会话之间转移；EOF、错误、心跳驱逐和握手失败都归还每 IP 配额。
- 修复最后一个 IP 配额释放时的锁重入死锁，以及 EOF 后在线表滞留；清理旧连接不会误删同地址的新连接。
- 每连接处理许可覆盖排队、handler 执行及响应入队，panic 也会归还许可；正常读取 EOF 排空已接收请求的响应。
- 涉及：`connection_limiter.rs`、`connection_session.rs`、`server_common.rs`、`reactor.rs`、`lynn_user.rs`；Issue #46、#49、#51、#55，PR #60。

### 3. fix — 客户端所有权与服务端 I/O 超时

- 释放 `LynnClient` 或取消启动会取消连接、读写、重连和心跳任务；克隆 sender 不再意外延长连接生命周期。
- 服务端已有读写超时配置真正作用于明文与 TLS I/O：读取按空闲续期，每条响应的写入与刷新共用期限，最终关闭另计期限；零值禁用期限。
- 每条响应都执行刷新，避免 TLS 小响应滞留内部缓冲；超时关闭会话，不重试已部分写出的响应。
- 涉及：客户端监督任务、服务端配置/读写循环及 `io_timeout.rs`；Issue #50、#52，PR #59、#63。

### 4. fix / ci — 独立功能、监控与长连接稳定性

- 修复关闭默认功能后的独立客户端/服务端编译，为模块、示例、测试和基准声明真实 feature 依赖，并新增六种独立 feature 组合的 CI 检查与测试（#47，PR #56）。
- metrics 请求行累积到 CRLF 后再识别路由，支持合法 TCP 分片；保留 1024 字节上限并加入不随滴流重置的 5 秒整行期限（#53，PR #58）。
- 从结构化地址提取 IPv6 TLS 默认校验名称，保留显式名称优先及证书验证，不再把 IPv6 方括号传作 DNS 名称（#54，PR #61）。
- Reactor 空闲计数使用饱和增长，避免长空闲后整数溢出导致 worker 退出或计数回绕；原有退避档位不变（#48，PR #62）。

## 向后兼容性

- 默认 feature 组合、默认公共 API 用法和合法 wire format 不变；仅使用客户端或服务端时，应显式设置 `default-features = false` 及对应 feature。
- 错误帧现在结束连接，不再清空缓存后继续使用该连接；客户端仍按既有重连策略恢复。
- 单连接并发配额现在严格生效；过去意外超限的请求会按原有策略拒绝并告警，零许可仍拒绝请求。
- 非零读写超时现在会关闭慢连接；读超时不是完整帧总期限，持续有字节进展会续期。
- `LynnClient` Drop 是异步取消，不保证发送队列排空或 TLS `close_notify`；需要交付确认的业务应先完成协议交互，不能只保留 sender 后释放 owner。
- 每响应刷新可能改变 TLS 小消息合批与吞吐；本次未进行性能压测。正常 EOF 的响应排空也不等于无限等待，现有心跳驱逐仍可能终止长时间处理。

## 升级指南

1. 将依赖更新为 `lynn_tcp = "2.2.0"`；仅用单一角色时保留 `default-features = false` 和对应的 `server` / `client` feature。
2. 检查对错误帧恢复、超额并发、非零超时以及释放客户端后继续使用 sender 的依赖，按新的明确生命周期调整。
3. 需要 IPv6 TLS 时使用包含匹配 IP SAN 的受信任证书，或显式设置与证书一致的校验名称，不要关闭证书校验。
4. 在部署环境执行应用级兼容性与容量验证；本版本未包含中间件支持，也不以历史压测替代升级后的性能验证。
