# v1.2.5 变更日志

发布日期：2025-12-25

## 概述

本版本是一个重要的里程碑，首次引入了**生产级监控能力**。通过集成 Prometheus 生态系统，实现了全面的指标收集、HTTP 端点暴露、Grafana Dashboard 和完整的文档支持。这使得 Lynn TCP 框架成为企业级应用的可选方案。

## 🎯 核心特性

### Prometheus 监控集成

采用业界标准的 **Prometheus + Grafana** 监控方案，这是云原生应用的首选监控方案。

**架构图**：
```
┌─────────────┐      /metrics      ┌─────────────┐
│ Lynn TCP    │ ─────────────────► │ Prometheus  │
│  Application │  (HTTP pull/10s)  │   Server    │
└─────────────┘                    └─────────────┘
                                            │
                                            ▼
                                    ┌─────────────┐
                                    │   Grafana   │
                                    │  Dashboard  │
                                    └─────────────┘
```

## 📊 监控指标详解

### 连接指标

| 指标名称 | 类型 | 描述 | 使用场景 |
|---------|------|------|---------|
| `lynn_connections_total` | Counter | 累计连接总数 | 容量规划 |
| `lynn_connections_active` | Gauge | 当前活跃连接数 | 实时监控 |
| `lynn_connections_closed_total` | Counter | 累计关闭连接数 | 连接稳定性 |
| `lynn_connections_failed_total` | Counter | 累计失败连接数 | 网络健康度 |

**PromQL 示例**：
```promql
# 查询当前活跃连接数
lynn_connections_active

# 每秒新建连接速率
rate(lynn_connections_total[1m])

# 连接失败率
rate(lynn_connections_failed_total[5m]) / rate(lynn_connections_total[5m])
```

### 消息指标

| 指标名称 | 类型 | 描述 | Bucket/Label |
|---------|------|------|------------|
| `lynn_messages_received_total` | Counter | 累计接收消息数 | - |
| `lynn_messages_sent_total` | Counter | 累计发送消息数 | - |
| `lynn_messages_invalid_total` | Counter | 累计无效消息数 | - |
| `lynn_messages_dropped_total` | Counter | 累计丢弃消息数 | - |
| `lynn_message_size_bytes` | Histogram | 消息大小分布 | 128B~1MB |
| `lynn_message_processing_duration_seconds` | Histogram | 消息处理时间 | 1ms~5s |

**PromQL 示例**：
```promql
# 消息吞吐量 (每秒)
rate(lynn_messages_received_total[1m])

# P95 消息处理延迟
histogram_quantile(0.95, rate(lynn_message_processing_duration_seconds_bucket[5m]))

# P50 消息大小
histogram_quantile(0.50, rate(lynn_message_size_bytes_bucket[5m]))

# 错误率
sum(rate(lynn_messages_invalid_total[5m])) / sum(rate(lynn_messages_received_total[5m]))
```

### 网络指标

| 指标名称 | 类型 | 描述 | 用途 |
|---------|------|------|------|
| `lynn_network_bytes_received_total` | Counter | 累计接收字节数 | 带宽监控 |
| `lynn_network_bytes_sent_total` | Counter | 累计发送字节数 | 带宽监控 |
| `lynn_network_tcp_retransmits_total` | Counter | TCP 重传次数 | 网络质量 |
| `lynn_network_tcp_errors_total` | Counter | TCP 错误次数 | 网络健康度 |

**PromQL 示例**：
```promql
# 网络吞吐量 (bytes/s)
sum(rate(lynn_network_bytes_received_total[1m])) + sum(rate(lynn_network_bytes_sent_total[1m]))

# 转换为 MB/s
(sum(rate(lynn_network_bytes_received_total[1m])) + sum(rate(lynn_network_bytes_sent_total[1m]))) / 1024 / 1024

# TCP 重传率
rate(lynn_network_tcp_retransmits_total[5m]) / rate(lynn_network_bytes_sent_total[5m])
```

### 系统指标

| 指标名称 | 类型 | 描述 | 用途 |
|---------|------|------|------|
| `lynn_system_memory_used_bytes` | Gauge | 内存使用量 | 资源监控 |
| `lynn_system_active_threads` | Gauge | 活跃线程数 | 并发监控 |
| `lynn_system_queue_size` | Gauge | 任务队列长度 | 性能瓶颈 |

**PromQL 示例**：
```promql
# 内存使用 (MB)
lynn_system_memory_used_bytes / 1024 / 1024

# 线程利用率
lynn_system_active_threads / 16  # 假设最大16个线程
```

### 2. Timer 辅助工具

**功能**：自动计时并记录到 Histogram

```rust
pub trait Timer {
    fn observe_duration<F, R>(&self, f: F) -> R
    where F: FnOnce() -> R;
}

impl Timer for Histogram {
    fn observe_duration<F, R>(&self, f: F) -> R {
        let start = std::time::Instant::now();
        let result = f();
        let duration = start.elapsed().as_secs_f64();
        self.observe(duration);
        result
    }
}
```

**使用**：
```rust
METRICS.messages.processing_duration_seconds.observe_duration(|| {
    // 处理消息...
    HandlerResult::new_without_send()
});
```

### 优化措施

- ✅ Prometheus 采用拉取模式，应用无额外开销
- ✅ Counter/Gauge 为原子操作，性能最优

## 🎓 最佳实践

### 1. 指标命名规范

遵循 Prometheus 命名约定：
```
lynn_<module>_<name>_<unit>

✅ lynn_connections_total
✅ lynn_messages_received_total
✅ lynn_system_memory_used_bytes
❌ connection_count
❌ message_rate
```

### 2. 指标类型选择

| 场景 | 推荐类型 | 原因 |
|------|---------|------|
| 计数器 (只增不减) | Counter | 单调递增，支持 rate() |
| 当前值 (可增可减) | Gauge | 可上下波动 |
| 分布/延迟 | Histogram | 统计分位数 |
| 多维度分类 | CounterVec/GaugeVec | 支持标签 |

### 3. Histogram Buckets 设计

根据实际数据分布选择：
```rust
// 消息大小 (偏小，长尾分布)
buckets(vec![0.0, 128.0, 512.0, 2048.0, 10240.0, 102400.0, 1048576.0])

// 处理时间 (偏小，99% < 100ms)
buckets(vec![0.001, 0.005, 0.01, 0.025, 0.05, 0.1, 0.5, 1.0, 5.0])
```

### 4. 避免高基数

❌ **不推荐**：
```rust
pub user_id: CounterVec,  // 每个用户一个标签 → 基数爆炸
```

✅ **推荐**：
```rust
pub user_connections_total: Counter,  // 总数
pub user_connections_by_type: CounterVec,  // 按类型分类
```

### 5. Scrape 间隔

| 环境 | 推荐 | 原因 |
|------|------|------|
| 开发 | 30s | 实时性要求不高 |
| 测试 | 15s | 及时发现问题 |
| 生产 | 10s | 平衡实时性和开销 |
| 大规模 | 30-60s | 降低 Prometheus 负载 |

- ✅ **生产级实现** - 低开销、高可用
- ✅ **完善的文档** - 从入门到最佳实践
- ✅ **即用型 Dashboard** - 开箱即用
- ✅ **完全向后兼容** - 无缝集成

**适用场景**：
- 生产环境监控
- 性能分析和优化
- 故障排查
- 容量规划
- 告警通知

**不适用场景**：
- 单元测试（建议 mock）
- 超低延迟场景（<1μs）
- 极端资源受限环境

**升级建议**：
对于所有生产环境部署，强烈推荐升级到 v1.3.0 并启用 metrics 功能。
