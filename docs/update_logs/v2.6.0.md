# v2.6.0 变更日志

发布日期：2026-11-06

## 概述

本版本增加可等待的服务端启动结果、客户端连接状态与重连代次、原会话定向推送及关闭观察、服务端限时排空，以及默认关闭的 KCP+TLS 1.3 业务流加密。应用可围绕真实启动地址和具体会话身份管理后台任务，并在计划停机时停止准入、完成已接受工作后关闭传输。

TCP 仍为默认传输，普通 Handler、帧格式与已有配置继续可用。新 `kcp-tls` feature 复用锁定的 rustls、tokio-rustls 与 kcp-ovo 0.8.0，不引入加密协议实现或自动传输降级。TLS 保护业务字节流，外层 KCP 控制报文仍没有认证。

## 主要变更

### 1. feat — 启动就绪与客户端连接状态

- `LynnServer::startup_handle()` 返回可克隆的 `ServerReady`，`wait()` 等待配置、绑定、TLS acceptor 及 worker 初始化并返回实际 `SocketAddr`。直接绑定 `127.0.0.1:0` 后可取得真实端口，多个实例和晚等待相互隔离；原始启动错误仍由 `start()` 返回。
- `LynnClient::subscribe_connection_state()` 提供独立 Tokio watch receiver，快照为带 `generation` 的 `Connected`、`Reconnecting` 或 `Stopped`。首次传输成功为代次 1，成功重连递增；未启动或初次连接失败不开放订阅。
- 监督任务是唯一状态发布者，正常终止先关闭发送准入和接收生产端再发布 Stopped。Drop、取消和重新启动以旧通道关闭作为结束信号，缓存 Connected 不能继续当作在线依据。watch 可合并中间变化，代次不标记逐帧归属，也不恢复业务鉴权。
- 完成 [#104](https://github.com/cherish-ltt/lynn_tcp/issues/104) / [PR #105](https://github.com/cherish-ltt/lynn_tcp/pull/105) 和 [#93](https://github.com/cherish-ltt/lynn_tcp/issues/93) / [PR #106](https://github.com/cherish-ltt/lynn_tcp/pull/106)。

### 2. feat — 原会话定向发送与最终关闭通知

- `RequestContext::session()` 与 `MiddlewareRequest::session()` 暴露请求入队前绑定的 `SessionHandle`，旧请求即使延迟执行也不会取得同址重连后的新会话。
- `try_send(method_id, Bytes)` 非等待向原有界 writer 入队，返回 `Enqueued`、`Full` 或 `Closed`；复用长度校验、实例帧标记和发送指标，保留普通 Handler 响应的等待背压。句柄不保活 owner、I/O 或 AppState。
- `observer()` 单独授予可取消、可重复的关闭等待能力，`SessionId` 支持进程内相等比较与哈希。通知发生在本地 transport 两端及 KCP driver 实际释放后；正常 EOF 先完成已接受请求链、响应入队和 writer shutdown。
- 应用须在保存私人推送句柄前完成授权，并在清理记录前比较身份；Handler 持有处理许可时不能等待本会话关闭。详见 [会话指南](https://github.com/cherish-ltt/lynn_tcp/blob/v2.6.0/docs/session-handles.md) 与 `session_push` 示例。
- 完成 [#102](https://github.com/cherish-ltt/lynn_tcp/issues/102)、[#103](https://github.com/cherish-ltt/lynn_tcp/issues/103) / [PR #107](https://github.com/cherish-ltt/lynn_tcp/pull/107)。

### 3. feat — 有总期限的排空停机

- `start_with_shutdown(signal, grace)` 接受应用提供的停止信号和一次总期限，返回 `lynn_tcp::Result<ShutdownOutcome>`，结果区分 `Drained`、`Incomplete`、`TimedOut`；初始化成功后才观察信号，总期限从观察到信号开始，启动失败保留原错误类型。
- 停止新连接、业务请求和后台发送准入，全实例已接受 Handler/中间件及其跨连接响应入队完成后，排空 writer 并关闭传输。KCP 保留已建立会话的 UDP 分派、ACK 与有序 EOF 驱动。
- 零期限明确强制取消；超时后取消并等待可取消任务和框架资源释放。请求失败、响应入队失败和关闭错误不伪报 Drained；该结果也不是业务交付确认。
- `start()`、Drop 和取消启动 future 保留原来的立即取消语义。Tokio 协作式取消不能抢占永不让出执行权的同步代码；超时也不回滚副作用。
- 完成 [#92](https://github.com/cherish-ltt/lynn_tcp/issues/92) / [PR #109](https://github.com/cherish-ltt/lynn_tcp/pull/109)，用法及边界见 [限时排空指南](https://github.com/cherish-ltt/lynn_tcp/blob/v2.6.0/docs/graceful-shutdown.md)。

### 4. feat / sec — 可选 KCP+TLS 1.3

- 显式启用 `kcp-tls` 并在双端同时配置 `with_kcp` 与 `with_tls`。只开 `kcp,tls` 的旧拒绝行为保留；新安全 HELLO 模式与明文模式严格区分，不自动降级。
- TLS 1.3 校验服务端 CA、IP/DNS 名称，可选 mTLS；安全模式拒绝跳过证书校验，禁用会话恢复、tickets、0-RTT 与 half-RTT 应用数据。客户端等待加密的服务端认证确认后才进入 Connected。
- 单次连接总期限覆盖 KCP、TLS 和确认阶段；服务端握手隔离于业务 worker，并保留独立并发上限、全局/每 IP 配额及取消所有权。网络指标仅统计解密后的框架字节，不计握手、TLS record 开销或 KCP 重传。
- 正常关闭先 TLS close_notify 后 KCP EOF；异常截断显式失败，可能部分写出的帧不自动重发。最大 10 MiB frame body、已有有界队列和背压继续有效。
- 完成 [#94](https://github.com/cherish-ltt/lynn_tcp/issues/94) / [PR #108](https://github.com/cherish-ltt/lynn_tcp/pull/108)。设计、配置与迁移见 [KCP+TLS 指南](https://github.com/cherish-ltt/lynn_tcp/blob/v2.6.0/docs/kcp-tls.md)、[KCP 场景选择](https://github.com/cherish-ltt/lynn_tcp/blob/v2.6.0/docs/kcp.md) 和 [独立进程性能对照](https://github.com/cherish-ltt/lynn_tcp/blob/v2.6.0/docs/kcp-tls-performance.md)。

## 向后兼容性

公开能力均为增量 API，Rust 1.99.1、Tokio `=1.52.3`、bytes `=1.11.1`、可选 kcp-ovo `=0.8.0` 及默认 feature 保持不变。明文 KCP 使用原 HELLO 模式；安全模式要求协同升级双端、UDP 可达和有效证书，既不兼容明文对端也不兼容标准 KCP/上游高层 API。

就绪不是实时健康，Connected 不是业务认证；推送入队、传输 ACK 和 Drained 均不是应用交付确认。外层 UDP/KCP 的 ACK、窗口、序号、地址和控制流仍可被干扰；本功能不提供抗 DoS、隐藏流量元数据或公网 SLA。

## 升级指南

1. 更新为 `lynn_tcp = "=2.6.0"` 并刷新 lock，使用 Rust 1.99.1。已有普通路由、Handler 与 TCP 配置可继续使用。
2. 服务端依赖启动结果时，在消费 server 前获取 `startup_handle()`，由其返回真实地址；客户端从状态订阅读取初始快照，并处理 changed 通道关闭。
3. 使用 `session_push` 示例了解注册返回、后台定向推送及按 SessionId 清理；使用 `graceful_shutdown` 示例接入应用自己的停止信号与总期限。
4. 使用加密 UDP 时选择 `default-features = false, features = ["server", "client", "kcp-tls"]`，双端显式配置 KCP 和 TLS，按指南分发信任锚、验证名称及可选客户端证书。仅需单端角色时移除另一角色。
5. 从更早版本升级仍须遵守 [v2.3.0 返回类型变更](https://github.com/cherish-ltt/lynn_tcp/blob/v2.6.0/docs/update_logs/v2.3.0.md)、[指标迁移](https://github.com/cherish-ltt/lynn_tcp/blob/v2.6.0/METRICS.md) 与 kcp-ovo 0.8.0 配置类型边界。
