# v2.4.1 变更日志

发布日期：2026-11-04

## 概述

合入 [PR #96](https://github.com/cherish-ltt/lynn_tcp/pull/96)，将可选 KCP 依赖从 kcp-ovo `=0.5.2` 升级至 `=0.6.0`，补充下游兼容契约与同源码新旧配对性能证据。TCP 仍为默认，传输适配、自定义 fast 参数、帧协议和生命周期语义不变。

这是依赖维护版本，不是普遍提速承诺：小包纯回环出现局部改善，高丢包出现下降，大消息结果方向不稳定。虽然版本号为补丁版本，直接混用旧版上游配置类型的应用仍需迁移。

## 主要变更

### 1. build / perf — 接入 kcp-ovo 0.6.0

- 精确锁定 `kcp-ovo =0.6.0`，核对官方发布包 checksum；不顺带升级其他依赖，Rust 1.99.1、Tokio 1.52.3、bytes 1.11.1 不变。
- 上游优化借用报文解析、单段接收、ACK 查找/RTT 合并、乱序队列插入与临时分配，保留 allocator 及连续超时退避修复；不 fork 或私改上游。
- 本项目 `src/`、`benches/` 未因本次升级修改；默认关闭 `kcp`、显式 `with_kcp`、HELLO/DATA/EOF 消息边界、有界队列、10 MiB body 上限与 ACK flush 均保留。
- 涉及 `Cargo.toml` / `Cargo.lock`、双语 README、KCP 指南和研究文档，双端配置与选择建议见 [KCP 配置、迁移与场景指南](https://github.com/cherish-ltt/lynn_tcp/blob/v2.4.1/docs/kcp.md)。

### 2. test — 依赖兼容与配对验证

- `tests/kcp_dependency_contract.rs` 新增 fast/normal 下输入缓冲覆写释放、单段/多段内容完整性，以及乱序/重复、满接收窗口恢复回归；保留应用自选 allocator 与 RTO 期限契约。
- 同一测试分别在 0.5.2/0.6.0 各 4 passed，属于升级兼容约束，不声称旧版存在已复现缺陷。
- 新旧依赖使用相同源码、独立 release target、同参数和独立服务进程，构建结束后串行交错测量；完整记录正负结果、退出码、请求/回复、qdisc、源码/二进制哈希与复跑脚本。

## 向后兼容性

- 默认 TCP、普通 builder、合法帧格式及业务 handler 用法不变；没有新增功能开关或自动降级行为。
- **`KcpConfig.protocol` 暴露上游配置类型。** 另行依赖 kcp-ovo 0.5.2 并将其类型传入的应用须同步升级至 0.6.0，或使用本库 `lynn_kcp::KcpOptions` 重导出；不能认为补丁版本意味着所有下游源码无条件兼容。
- KCP 仍无加密/认证，不兼容标准 KCP 或上游高层 API；TLS+KCP 明确拒绝，敏感或不可信链路继续优先 TCP+TLS。fast 的 `nocwnd=true` 不保证共享链路公平性。
- flush 的传输 ACK 不是业务交付，Drop 不承诺排空；需要交付确认时仍须应用协议交互。

PR #96 的 Head `8375e1867a63d3dc51af708f10c84b096366d7b2` 经验证后 Squash 为 `1ab96be16836561d63c25628db9241befb5a94ac`，两者文件树完全一致；[PR CI](https://github.com/cherish-ltt/lynn_tcp/actions/runs/41800954782) 11/11 jobs 通过。

- 发布前验证（依赖已升级至 0.6.0）：默认 171、全 feature 225 tests passed（含 7 doctest），十种独立 feature check/test 通过；单独覆盖率运行 218 tests，行覆盖 92.97%（4165/4480），无覆盖率 warning，不含上游库覆盖。
- 独立进程 TCP/fast/normal 各 800/800 内容一致；metrics 黑盒 400/400 回复、5/5 连接关闭、收发各 9200 B 精确匹配；格式、Clippy、build 与全量 prek 通过。
- 发布前配对性能：32 并发、每连接一个在途请求、三轮吞吐中位数，原矩阵 5 秒窗口、独立补测 10 秒窗口，分开统计。

|---|---:|---:|---:|---:|
| 128 B，无 netem | 22289.2 | 26322.0 | +18.1% | +9.8% |

TCP 对照同样明显波动，逐轮 KCP 变化并不一致；不能把中位数比值当成统计显著或稳定提速。高丢包下降尚未定位，不能由正向结果掩盖，也未证实为上游缺陷。

132 次命令、228 格均正常退出，无内容断言失败；原矩阵有限尾部差值 149（旧/新 KCP 1/4、TCP 74/70），补测差值 99（KCP 1/2、TCP 49/47）。原矩阵还有 1 格 0 请求/0 回复，全部保留；进程成功不代表业务进展或全数交付，差值不能认定为永久丢失。

完整证据见 [0.6.0 配对验收报告](https://github.com/cherish-ltt/lynn_tcp/blob/v2.4.1/docs/kcp-v0.6.0-validation.md) 与 [原始 JSON](https://github.com/cherish-ltt/lynn_tcp/blob/v2.4.1/docs/benchmark/v2.4.0-arm64-kcp-0.6.0-paired-study.json)。原始文件名与被测版本仍为发布前 v2.4.0 基线，不代表修改为 v2.4.1 后重新压测。

未测公网跨主机、Windows、长时间 soak、1024/4096 并发、限带宽拥塞/公平性、突发相关丢包、normal 性能矩阵及 CPU/内存 profile；本次发布不重复压测与覆盖率。新版本打包、CI 和发布状态单独核验，不使用旧测试代替正式发布成功。

## 升级指南

1. 将依赖更新为 `lynn_tcp = "=2.4.1"` 并刷新 lock，保留 Rust 1.99.1 及兼容的 Tokio/bytes 约束；仅用 TCP 不必启用 KCP。
2. 使用 KCP 时，双端启用 `kcp` 并调用 `with_kcp(KcpConfig::default())`；直接传入上游配置的应用同步升级 kcp-ovo 或使用 `lynn_kcp::KcpOptions`。
3. 沿用 [KCP 配置与迁移](https://github.com/cherish-ltt/lynn_tcp/blob/v2.4.1/docs/kcp.md)，不要开启原生 stream_mode 或叠加 TLS；在真实 payload、并发、带宽与丢包分布下验收，而非预设新版更快。
4. 从 v2.4.0 之前升级时，继续应用 [指标迁移](https://github.com/cherish-ltt/lynn_tcp/blob/v2.4.1/METRICS.md#自动采集边界与迁移) 和 [v2.3.0 返回类型变更](https://github.com/cherish-ltt/lynn_tcp/blob/v2.4.1/docs/update_logs/v2.3.0.md#升级指南)。
