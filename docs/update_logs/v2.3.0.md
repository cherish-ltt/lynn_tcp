# v2.3.0 变更日志

发布日期：2026-11-03

## 概述

通过 12 个 PR（#77-#88）修复 11 个 bug Issue（#64-#73、#75）及 1 项 TLS 握手安全反馈。重点是连接准入和任务生命周期、TLS 传输可靠性、协议边界以及向调用方显式返回错误。

本版本包含源码不兼容的公共 API 返回类型变更：`LynnServer::start()` 返回 `lynn_tcp::Result<()>`，两个发送消息构造器返回 `lynn_tcp::Result<HandlerResult>`。合法报文格式与默认 feature 不变；升级前必须适配调用方，不能按完全兼容的次版本更新处理。

## 主要变更

### 1. sec — TLS 握手隔离与有界并发

- TLS 连接初始化移出业务 worker，避免静默握手耗尽 worker 后阻塞已有连接的请求。
- 握手并发上限为配置的业务 worker 数，先取得许可再创建任务；超限立即拒绝，不创建无限等待的后台任务。
- 保留全局/每 IP 连接配额和原有 10 秒握手超时；成功、失败、超时及服务取消均归还资源。
- 涉及 `server_common.rs`、`reactor.rs` 和真实 TLS 回归；PR #81。
- 此前的错误帧接收缓冲区安全反馈已由 PR #57 在 v2.2.0 修复，本轮复核后说明并关闭。两条安全反馈均保持关闭、未发布公告且未分配 CVE；本版本通过公开 PR 交付修复。

### 2. fix — 全局准入、服务端取消和启动结果

- 全局连接配额在 accept 后立即预留，覆盖排队、握手和活跃会话，而非仅统计在线表；`None` 仍表示不设全局上限（#66，PR #79）。
- 服务端 owner 统一取消分派、worker、handler、读写、心跳和清理任务；释放未启动实例或取消 `start()` 不再遗留任务、连接和状态（#67，PR #80）。
- `LynnServer::start()` 向调用方返回监听绑定、TLS 初始化等错误，保留错误类型；示例和监督任务同步处理结果（#69，PR #77）。
- 任务池大小为零时在监听前返回配置错误，新旧 setter 采用同一约束；正值和其他零值禁用配置不变（#70，PR #78）。
- 涉及 `lynn_server.rs`、`server_tasks.rs`、`connection_session.rs`、`connection_limiter.rs` 和服务端回归测试。

### 3. fix — 客户端 TLS 刷新、重连和 mTLS 身份

- 每帧写入后刷新，解除 TLS 背压后最后一帧无需等待后续消息或心跳；写入/刷新失败结束连接，阻塞刷新可取消，不重试可能已部分发送的帧（#64，PR #82）。
- 连接失败和已建立连接结束后均遵守重连间隔，避免对端接受后立即关闭导致快速重连；首次尝试仍立即执行，零值禁用等待（#65，PR #83）。
- 显式跳过服务端证书校验不再丢弃客户端 mTLS 身份，缺失配对证书/密钥及无效身份仍显式报错；默认仍校验服务端证书（#73，PR #86）。
- 修正双语 README 的 TLS 客户端配置示例，`.with_tls(...)` 不再错误使用 `?`，并加入文档片段编译回归（#75，PR #87）。
- 涉及客户端写入/监督任务、`tls_provider.rs`、双语 README 和 TCP/TLS 回归。

### 4. fix — 协议实例隔离与消息边界

- 帧头/帧尾标记随服务端实例传递；同进程同时或先后启动不同协议标记的服务端不再互相污染响应（#68，PR #84）。
- 字符串字段可读取空串及 1/2 字节短串，不再误用完整帧最小长度；长度超限或越界不推进游标（#71，PR #85）。
- `HandlerResult::new_with_send` / `new_with_send_to_server` 在构造边界校验长度，payload 超过 10 MiB 减 5 字节时返回 `LynnError::Protocol`，先于完整帧分配和入队；原始 sender、克隆及广播均不能绕过（#72，PR #88）。
- 涉及 `handler_result.rs`、`input_buf_vo.rs`、实例配置传递，以及全部受返回类型变更影响的示例、测试和调用方。

## 向后兼容性

- **源码不兼容：**`LynnServer::start()` 从 `()` 改为 `Result<()>`；例如 `JoinHandle<()>` 需要改为承载新返回类型或在任务内显式处理错误。
- **源码不兼容：**两个发送构造器从 `HandlerResult` 改为 `Result<HandlerResult>`。支持传播错误的调用方可使用 `?`；返回 `HandlerResult` 的 handler 应显式处理构造失败，不能把错误静默当作发送成功。`new_without_send` 和心跳行为不变。
- 合法 wire format、默认 feature、单一角色配置方式及 TLS 1.3 基线不变；本地超限发送被拒绝，但不截断消息或关闭健康连接，入队成功不等于交付成功。
- 全局配额现在覆盖排队与握手，TLS 握手超限会立即拒绝；突发连接的接受行为比此前更严格。
- 服务取消为异步强制取消，不保证队列排空或 TLS 优雅关闭，也不能抢占用户 handler 中不让出执行权的同步死循环。
- 逐帧刷新及断线后等待可能改变合批、吞吐和重连时序；本轮未重跑性能基准，历史基准不代表 v2.3.0 的实测性能。

## 升级指南

1. 更新依赖为 `lynn_tcp = "2.3.0"`；独立角色继续设置 `default-features = false` 和对应 feature。
2. 处理 `server.start().await` 的结果，例如在返回兼容错误类型的入口使用 `server.start().await?`；同步调整监督任务返回类型。
3. 为两个发送构造器增加 `?` 或显式错误分支；动态 payload 应在业务侧限制大小并向调用方报告拒绝，避免用无条件 `unwrap()` 处理不可信输入。
4. 确保任务池至少为 1，按部署容量检查全局连接和握手上限，并在取消服务前完成需要确认交付的交互。
5. 在目标环境验证业务兼容性和容量。本版本不包含 #74 指标接入及 #76 TCP/KCP 双传输增强。
