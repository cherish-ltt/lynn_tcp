# v2.4.0 变更日志

发布日期：2026-11-03

## 概述

合入 [PR #89](https://github.com/cherish-ltt/lynn_tcp/pull/89)（#74 真实传输指标）与 [PR #90](https://github.com/cherish-ltt/lynn_tcp/pull/90)（#76 可选 TCP/KCP 双传输）。TCP 仍为默认；KCP 使用 kcp-ovo `=0.5.2` 底层控制块和自定义 fast 配置，两端复用既有业务 handler、路由、状态及帧协议。

KCP 是明确的部署选项，不是普遍提速或安全传输承诺。已有 20 ms RTT 小包弱网实测支持高丢包优势，但纯回环和部分低并发场景仍落后 TCP；已知上游 allocator/RTO 缺陷均已修复并完成下游验证，不再等待上游。

## 主要变更

### 1. feat — 底层 KCP 接入与显式配置

- 新增默认关闭的 `kcp` feature，双端 builder 使用 `with_kcp(KcpConfig)`；独立角色可用 `client,kcp` / `server,kcp`，同一实例只选择一种传输，无自动回退或同时监听。
- 直接使用 `kcp_ovo::core::kcp::Kcp`，不使用上游高阶 Stream/Listener；自定义 fast 为 true/10ms/2/true，新数据与 ACK 即时输出，周期 tick 负责重传及空闲检查；保留 normal 和自定义参数。
- 消息/流模式与 fast/normal 独立：适配向框架提供字节流，但 HELLO/DATA/EOF 依赖 KCP 消息边界，`stream_mode=true` 明确拒绝。
- 保留连接/每 IP/速率限制、owner 取消、重连、超时、10 MiB body 上限与有界队列；KCP flush 等待传输 ACK，不代表 handler 成功，Drop 不排空。
- 涉及双端配置/连接入口、`src/infrastructure/kcp/`、统一监听/流抽象、示例与真实 UDP/进程黑盒回归；详见 [KCP 配置、迁移与场景指南](https://github.com/cherish-ltt/lynn_tcp/blob/v2.4.0/docs/kcp.md)。

### 2. feat — 真实连接、消息与网络指标

- 连接计数随 accept/准入/握手/会话所有权转移，释放时恰好回收一次；区分初始化失败和已建立连接结束。
- 网络字节按成功的实际读写长度累计；接收按完整帧解析、发送按完整写入和刷新、处理时间按 handler 执行边界统计。
- TCP、TLS、KCP 共用服务端指标；示例用真实 echo 流量，不再伪造内存/线程等数值，新增 exporter 和独立进程黑盒验证。
- 同进程多服务端聚合，客户端不自动采集；字节不是线路开销/重传统计。系统内存/线程/队列及 TCP 重传/错误仍需外部采集，零值不代表健康。迁移须删除重复的手工内置指标累加，见 [监控指南](https://github.com/cherish-ltt/lynn_tcp/blob/v2.4.0/METRICS.md#自动采集边界与迁移)。

### 3. fix / build / test — 依赖契约、性能根因与证据

- Rust/MSRV、CI、Clippy 统一为 **1.99.1**；为满足上游精确依赖，Tokio 从 1.53.1 调整至 `=1.52.3`，bytes 从 1.12.1 调整至 `=1.11.1`，默认 TCP 构建也受影响。
- kcp-ovo 固定 `=0.5.2`，移除其旧版库级 allocator 冲突（上游 #36），修正 fast/normal 超时退避及下一次重传期限（上游 #38）；保留下游自选分配器和连续 RTO 契约回归，没有 fork 或私改上游。
- 修复适配层数据/ACK 等待 tick 的性能问题；修正 benchmark model 1 用回复回填请求数的问题，改为独立计数与逐内容校验，保留缺失响应而不以成功退出冒充交付。
- CI 扩展至十种独立 feature 组合；保留 fast/normal/TCP 进程黑盒、取消/重连/背压/损坏输入/UDP 丢包乱序等回归，发布准备移除临时堆叠基线过滤。

## 向后兼容性

- 相对 v2.3.0，默认 TCP 和合法业务帧格式不变；新增 KCP API 为 opt-in，原有 `start()`/发送构造器的 `Result` 契约保持不变。早于 v2.3.0 的调用方仍须先适配 [v2.3.0 返回类型变更](https://github.com/cherish-ltt/lynn_tcp/blob/v2.4.0/docs/update_logs/v2.3.0.md#升级指南)。
- MSRV 提升与精确依赖调整可能影响下游构建；若应用也精确锁定不兼容的 Tokio/bytes 版本，应协同调整并实测，不能假定可并存两份 semver-compatible 精确版本。
- 指标现在自动累计，继续手工累加同一内置指标将双计数；内置自动采集不提供关闭开关。
- KCP 无加密/认证，不兼容标准 KCP 或上游高阶 API；TLS+KCP 拒绝启动，敏感/不可信网络继续优先 TCP+TLS。fast 的 `nocwnd=true` 可能牺牲共享链路公平性，不推荐无带宽约束地直接部署共享公网。
- 传输 ACK 不等价于业务交付；UDP 远端消失依靠 idle 回收（默认 60 秒），需要可靠交付的业务应先完成应用层确认再释放 owner。

- 已验证 `c9abd3f`：默认 171 项、全 feature 223 项（含 7 doctest）通过，十种独立 feature check/test 全部通过；覆盖率另跑 216 项，行覆盖 **92.68%（4152/4480）**，无数据不匹配告警，不含上游覆盖率。

- Linux 隔离容器 netem，128 B、32 并发、每连接一个在途请求、每格全新服务进程、1 秒预热/5 秒测量、三轮中位数：

主测试 42 次/84 格，500 ms 尾部接收，累计 1,706,037 请求 / 1,705,957 内容校验回复，**80 个差值（TCP 76、KCP 4）**；不能宣称全部交付或直接认定协议永久丢失。独立 30 秒诊断中 KCP 15336/15336、TCP 3036/3036，但不是相同轨迹重放，不能覆盖主测试差值。每方向 10 ms、独立随机包丢失、无带宽限制，不等同业务请求丢失率或拥塞测试。

## 升级指南

1. 安装 Rust 1.99.1，更新 `lynn_tcp = "=2.4.0"` 和 lock；核对应用直接依赖的 Tokio/bytes 约束。只用 TCP 无须启用 KCP。
2. 选 KCP 时，双端启用 `kcp` 并配置 `with_kcp(KcpConfig::default())`，保留 handler 和协议标记；开放对应 UDP 端口，先验证目标网络 UDP 可达性，不修改宿主网络来套用压测命令。
3. 按 [迁移步骤与建议场景](https://github.com/cherish-ltt/lynn_tcp/blob/v2.4.0/docs/kcp.md) 选择 fast/normal/custom、核对超时/窗口和安全边界；不要开启原生 stream_mode 或叠加 TLS。若曾使用 PR 早期结构体字面量，补 `..KcpConfig::default()`。
4. 删除重复的内置指标手工累加，用真实请求、连接关闭和指标增量验收；业务指标另取名称。
5. 用真实业务 RTT、包大小、并发、带宽和丢包分布验收，保留 TCP/TCP+TLS 回退部署配置（框架不会自动回退），确认业务交付后再释放连接。
